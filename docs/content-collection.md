# 教材データの収集方針（iOS / App Store 審査対応）

読み上げ・シャドーイングに使う文章を、**App Store の審査を通り、かつ有料サブスクで配信し続けられる**形で集めるための方針。
判定ロジックは `src/lib/content-policy.ts`、動的収集は `src/lib/collect.ts` と `/api/v1/cron/collect` にある。

## 前提: 審査で見られる点

| ガイドライン | 内容 | このアプリでの対応 |
|---|---|---|
| 5.2.1 / 5.2.2 知的財産・第三者コンテンツ | 権利者の許可なく第三者の著作物を配信しない | カタログの全教材に出典とライセンスを持たせ、配信できるライセンスだけを公開する（DB制約でも強制） |
| 5.2.3 音声・動画のダウンロード | YouTube等の第三者ソースの音声・動画を保存・変換させない | iOS版ではYouTube字幕の取得・音声の取り出しをしない（後述） |
| 1.2 ユーザー生成コンテンツ | 共有されるUGCには通報・ブロック・フィルタが必要 | 利用者の取り込み文章は**本人専用で共有しない**。教材への通報は `POST /reports` |
| 5.1.1(v) アカウント削除 | アプリ内からアカウントを削除できること | `DELETE /me`（auth.users ごと削除、関連データは CASCADE） |
| 5.1.1 データ最小化 | 必要なデータだけを集める | 音声はサーバーに送らない。端末で包絡を作り、指標だけを保存する |
| 5.1.2(i) 第三者AIへのデータ送信 | 個人データを第三者AIに送るなら明示して同意を得る | 利用者の文章や発話をLLMに送る機能を入れる場合は、送信前に同意画面を出す |
| 3.1.1 / 3.1.2 課金 | デジタルコンテンツはIAP。サブスクには継続的な価値が必要 | 新着教材が定期的に増える（動的収集）ことがサブスクの根拠になる |
| 4.8 ログイン | 第三者ログインを使うならSign in with Apple相当も提供 | 匿名サインイン（ログインなしでも練習できる）＋ Sign in with Apple / Google / メール / パスキー。Google があるので Apple を併設 |
| 2.1 完全性 | 審査員がすぐ試せること | 教材一覧はログイン不要。初回起動で匿名サインインし、そのまま今日の課題に入れる |

## ライセンスの判定

有料アプリで配信し、文の分割・TTS音声化・訳付けといった**派生物を作る**前提で判定する。

| ライセンス | 可否 | 理由 |
|---|---|---|
| original（自社作成） | ◎ レビューなしで公開可 | 権利が自社にある |
| public-domain / CC0 | ○ レビュー後に公開 | 米国政府の著作物、著作権切れ |
| CC BY | ○ 帰属表示が必須 | 営利・改変とも可 |
| CC BY-SA | △ 帰属表示＋派生物も BY-SA | 分割した文や音声も BY-SA で出す必要がある |
| licensed（個別契約） | ○ 契約IDが必須 | |
| CC BY-NC 系 | ✕ | 有料アプリは営利利用にあたる（**TEDトークは BY-NC-ND なので使えない**） |
| CC BY-ND 系 | ✕ | 文の分割・音声化は改変にあたる |
| unknown | ✕ | 出典確認まで公開しない |

パブリックドメインの配信元でも、**通信社（AP / Reuters / AFP）の配信記事や写真は通信社の著作物**なので、
`detectThirdPartyCredits` で検出してレビュー時の注意事項に残す。

## 1. 事前収集（ローンチ時のカタログ）

ローンチ時点で **レベルごとに最低100本（計300本）** を用意する。審査員が開いたときにカタログが空・薄いと、
2.1（完全性）や 4.2（最低限の機能）で落ちやすい。

### 1-a. 自社オリジナル（主力・最も安全）

- カリキュラム表（CEFR A2〜C1 × トピック × 練習させたい音の現象：連結・脱落・弱形など）を作り、
  LLMで下書きを生成 → 人が確認・修正 → `license: original` で登録する。
- **特定の記事を言い換えさせない**（派生物とみなされうる）。トピックと事実だけを渡して書かせる。
- 日本語訳もここで付ける（シャドテンの「スクリプト確認」ステップに必要）。
- 音声は、**再配布が許諾された商用TTS**で生成して `audioUrl` と文ごとの `startMs/endMs` を付ける。
  端末内蔵の音声（AVSpeechSynthesizer）は端末上の読み上げには使えるが、サーバーで生成して配る用途には使わない。

### 1-b. パブリックドメインのアーカイブ

| 配信元 | ライセンス | 向いている用途 | 注意 |
|---|---|---|---|
| VOA Learning English（2025年3月までのアーカイブ） | 米国政府著作物 | 初級〜中級。ゆっくりした語りと語彙が学習者向け | 2025年3月以降フィードの更新が止まっている（2026-10-12確認）。通信社クレジットのある記事・写真は除く |
| 米大統領・政府の演説（National Archives 等） | 米国政府著作物 | 上級。**実際の肉声音声もパブリックドメイン**なので、本物のお手本音声が手に入る | 音声の所蔵機関ごとに利用条件を確認 |
| Project Gutenberg の短編・随筆 | 著作権切れ（米国） | 上級・朗読 | 日本でも保護期間が切れているか確認。Gutenberg の商標表記は外す |
| LibriVox | パブリックドメイン（音声も） | 朗読シャドーイング。人の声のお手本 | 本文と音声の時刻合わせ（強制アライメント）が必要 |

VOA のアーカイブは `SOURCES` に `active: false` で登録してある。一括取り込み用のスクリプトで、
ここから取り込んだものも必ず `pending_review` を通す。

### 1-c. 既存ライブラリ（`src/lib/library-content.ts`）の扱い

いまの8本は出典表記が曖昧（「TED-style」「Public domain business content」など）で、
**このままでは iOS のカタログに載せられない**。`/api/v1` のローカル用メモリストアでは `license: "unknown"` として扱っている。
本番投入前に、出典を特定するか、1-a の手順でオリジナルとして書き直す。

## 2. 動的収集（ローンチ後に増やし続ける）

### 2-a. パブリックドメイン配信元の定期収集（実装済み）

`/api/v1/cron/collect` を1日1回実行する（`wrangler.jsonc` の Cron Trigger → `worker.ts` の `scheduled`）。

```
配信元フィード（SOURCES のうち active: true）
  → 記事URLを配信元ドメイン・パスで絞る（APODなど権利の違う記事を除外）
  → contentSelector で本文だけ抽出 → 署名・連絡先・リンク誘導を除去
  → 文に分割・レベル推定・ライセンス判定（content-policy）
  → materials に pending_review で保存（original 以外は自動公開しない）
  → 人がレビューして published に変更
```

登録済みの配信元:

- **NASA News Releases**（稼働中）— 米国政府著作物。同じフィードに混ざる APOD（science.nasa.gov）は、
  画像・文の権利が個別なので `allowedPathPrefix: "/news-release/"` で除外している。
- 追加候補: NIH News in Health（平易な英語の健康記事。米国政府著作物）、NOAA、National Park Service。
  追加するときは利用規約を確認し、この表に記録してから `SOURCES` に足す。

レビュー作業は当面 `wrangler d1 execute DB --remote --command "UPDATE materials SET status = 'published', published_at = ... WHERE id = ..."` で行う。件数が増えたら管理画面を作る。
DBの `publishable_license` 制約により、NC・ND・unknown の教材は誤って公開しようとしても弾かれる。

### 2-b. トピック起点のオリジナル生成（次の実装候補）

- その週の話題（ニュースの**トピックと事実**）を入力に、各レベル向けの文章をLLMで新規に書かせる。
- 1-a と同じく、人のレビューを経て `original` で公開する。音声は商用TTSで生成する。
- 定期収集の元が少ない時期でも、毎週一定の新着を出せる（サブスクの継続価値。3.1.2）。

### 2-c. 利用者による取り込み（実装済み・私的利用）

`POST /me/texts` で、利用者が自分の文章を練習教材にできる。

- iOS では **共有シート（Share Extension）からの受け渡しを主経路**にする。利用者が自分で選んだ文章を渡す形で、
  サーバーが第三者サイトを巡回しない。URL を渡す方法は補助。
- 取り込んだ文章は `user_texts` に**本人専用**で保存し、カタログには載せず、他の利用者とも共有しない。
  共有しないので 1.2（UGC）の通報・ブロックの仕組みは不要になり、著作物の再配布にもならない。
- アカウント削除で一緒に消える。

### 2-d. 利用データによる改善

- `weakSentences` と本番スコアの分布から、レベル設定が合っていない教材を見つけて付け直す。
- `POST /reports` の `copyright` 申し立ては、受けたら即座に非公開（`pending_review` に戻す）にして確認する。

## 3. YouTube モードの扱い（iOS版）

Web版の YouTube モードは、字幕テキストと時刻をブラウザ拡張（ShadowFeed）で取得している。
iOS では次の理由で **v1 には入れない**ことを推奨する。

- 字幕・音声を YouTube の公式APIの外から取得するのは YouTube の利用規約に反し、
  音声の取り出し・保存は審査ガイドライン 5.2.3 に抵触する。
- 公式の埋め込みプレーヤーで再生し、マイクで自分の声を録るだけなら可能。ただし、お手本の包絡を作るための
  タイムスタンプが手に入らないので「重なり」採点が成立しない（ADR-001 の影響欄と同じ制約）。

入れる場合は「埋め込み再生＋自分の録音を聞き返す」だけの採点なしの練習機能にする。

## 4. 申請前チェックリスト

- [ ] カタログの全教材に `license` と `source_url` があり、`unknown` が0件
- [ ] CC BY 系の教材は、アプリの教材画面に帰属表示（`attribution`）を出している
- [ ] 既存ライブラリ8本の出典を確定、または書き直し済み
- [ ] `NSMicrophoneUsageDescription` / `NSSpeechRecognitionUsageDescription` に用途を具体的に書いた
- [ ] プライバシーマニフェスト（`PrivacyInfo.xcprivacy`）を同梱し、App Store Connect のプライバシー欄に
      「練習記録（スコア）」「ユーザーID」を申告。音声は収集しない旨を明記
- [ ] プライバシーポリシーと利用規約のURL
- [ ] アプリ内にアカウント削除の導線（設定 → アカウントを削除 → `DELETE /me`）
- [ ] ログインなしで教材一覧と練習が試せる（匿名サインイン）
- [ ] サブスクを入れる場合は IAP（StoreKit）で、復元ボタンと規約・プライバシーポリシーへのリンクを置く
- [ ] 審査メモに「音声は端末内で処理し送信しない」「教材は自社作成またはパブリックドメイン」と書く
- [ ] 審査メモにメールログインのデモアカウント（`AUTH_REVIEW_EMAIL` と `AUTH_REVIEW_CODE`）を書く
